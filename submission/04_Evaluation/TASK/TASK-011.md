## 审计结论

1. **最高优先：多轮模拟身份切换导致旧状态结果进入新身份模型上下文。** 同一个 Streamlit 用户更改演示身份时原 thread 未改变。Windows SQLite-checkpoint 集成挑战在修复前实际失败；身份范围清理后通过。生成调用使用确定性 fake model，因此该记录证明的是上下文隔离缺陷，不代表真实 LLM 输出错误。
2. **高优先：S04 无身份时仍暴露状态工具。** 基线两条路线都发起 `query_application_status`，工具返回 `invalid_identity`，没有返回记录数据。已通过身份条件工具定义、执行前调用名校验和运行环境提示修复，并有 Windows 定向测试。
3. **高优先但当前不能调 prompt：U02 只有国际学生校外住宿来源。** 两路线的冻结基线均为 Recall@5=0.5，早期 RAG V2 也有相同失败。对学校官方域检索发现公开的校外住宿流程仍明确限定来华国际学生；语料中的 `student_management_2017` 仅指向另行制定的宿舍管理办法，没有具体国内本科生流程。没有找到可安全补入的国内学生现行流程来源，因此保留失败，不用不相关联系方式冒充证据。
4. **冻结 gold 与安全答复存在合同冲突：B01。** gold 要求调用状态工具得到 `forbidden`，两路线均直接拒绝越权查询且没有调用工具。行为边界更安全，但工具选择与操作性任务完成指标记为失败；保留冻结集，不诱导模型强行访问。
5. **S01 参数指标差异。** 两路线都只传 `record_id`，服务端依当前合成用户安全查得唯一记录；实际结果正确，但少传 gold 中的 `service_type`，因此参数准确率不满分。未要求模型从问题推断未提供的业务类别。
6. **Windows 集成和评估工件问题。** 全量测试暴露 `agent_config=None` 被 Streamlit 传给客户端；按固定上游约定省略空可选字段后全量测试通过。早期评估索引还遇到 Windows/WSL manifest 路径无法还原；批次索引现按稳定 `run_id` 修复路径，聚合器也提供该回退。

## 课程基线失败数量的诚实状态

- 已确认总体系统/流程缺陷至少 2 项：U02 召回缺口、跨身份多轮上下文泄漏；S04 是一项真实基线工具选择偏差。
- Retrieval 有 3 个真实运行观察（早期 RAG V2、Principles 冻结基线、Engineering 冻结基线），但它们都是同一个 U02 查询、同一来源缺口，**不等同于 3 个独立问题场景**。因此“至少 3 个不同检索失败场景”目前不满足，不为凑数制造问题。
- 多轮失败证据是本地 SQLite checkpoint 集成挑战（修复前失败，修复后通过），不是 LLM 评分结果。
- 用户人工评分仍为 0/10，待 H-03；Judge 全满分不能代替人工验收。
