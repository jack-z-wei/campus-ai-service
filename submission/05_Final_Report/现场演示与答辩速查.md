# 现场演示与答辩速查

这份速查用于课程现场演示。项目的演示页面由本机 Streamlit 前端连接本机 FastAPI 服务；当前可运行入口是本机地址 `http://127.0.0.1:8501`，不是 GitHub 上的在线网站。公开仓库用于查阅项目文件，打开仓库不会启动 Agent。

## 一、演示前快速启动

建议在 Windows 上提前确认项目虚拟环境可用、Ollama 已启动且装有 `bge-m3:latest`，项目 `.env` 中的回答模型配置有效。不要在投屏或截图中展示 `.env` 和密钥。

打开 Windows PowerShell，运行：

```powershell
Set-Location C:\Users\26313\Desktop\人工智能课设\campus-ai-service
.\.venv\Scripts\python.exe scripts\launch_local_demo_windows.py
```

启动器会启动 API 和网页前端，检查校园客服 Agent 已注册并自动打开浏览器。地址栏应为：

```text
http://127.0.0.1:8501
```

如果浏览器没有自动弹出，在地址栏手动输入上面的地址。启动器占用本机 `8080` 和 `8501` 端口；如果提示端口被占用，先结束之前启动的演示服务。首次准备环境或 `.venv` 不存在时，提前在项目目录运行 `uv sync --frozen`，不要留到演示开始后再安装依赖。

网页左侧点击“演示设置”，选择合成演示身份 **SIM-USER-002 · 宿舍维修**。本页面固定使用 `campus-customer-service`，不需要另选 Agent。演示数据是合成记录，不要输入真实学生的姓名、学号或联系方式。

启动器创建独立的 `runs/ui-preview-*` 数据目录。现场演示结束后，可从该目录的 `manifest.json` 读取服务进程号并在 PowerShell 停止服务：

```powershell
$run = Get-ChildItem .\runs -Directory -Filter 'ui-preview-*' | Sort-Object LastWriteTime | Select-Object -Last 1
$manifest = Get-Content (Join-Path $run.FullName 'manifest.json') | ConvertFrom-Json
Stop-Process -Id $manifest.api_pid, $manifest.streamlit_pid
```

## 二、约三分钟演示对话

点击侧栏“开始新咨询”，按下面顺序输入。重点展示回答中的来源、记录查询结果和第二轮追问，不必要求模型逐字说出示例预期文本。

### 1. 校园政策问答：展示 RAG 与来源

**我输入：**

> 长安大学本科生每学期修读多少学分比较合适？请说明超过后需要什么审批，并给出来源。

**现场讲解：**

> 这类问题会先检索整理好的校园资料，再把命中的内容交给语言模型组织答案。这里可以检查它引用的文件标题、适用范围和链接；材料是 2022 年试行文件，所以我会同时说明它的时效需要以学校最新通知为准。

预期核对：回答围绕来源支持的 15–35 学分范围及超出后的审批要求，并展示政策来源。政策结论以页面实际引用和项目快照为准，不把旧版试行材料说成当前有效的最终规定。

### 2. 查询模拟工单：展示工具调用

确认“演示设置”中的身份为 `SIM-USER-002 · 宿舍维修`，输入：

> 查一下我的宿舍报修单 SIM-REC-002。

预期核对：返回合成记录 `SIM-REC-002` 的状态“已派单”，记录更新时间为 `2026-09-27 14:30`。可指出 Agent 调用了状态查询工具，后端再按演示身份和记录归属核对 SQLite 中的记录。

### 3. 接着追问：展示 Memory 与本地模拟服务单

在上一条回答后直接输入：

> 基于这条记录，帮我转人工确认预计上门时间。

预期核对：Agent 能沿用上一轮的记录上下文，并返回本地模拟服务单结果。明确说明这是课程演示工单，不会联系真实工作人员，也不代表有人承诺上门时间。

### 4. 问资料未覆盖的问题：展示不编造

输入：

> 长安大学图书馆今天各馆区分别几点开门、几点闭馆？

预期核对：当前资料无法确认当天各馆区时段时，回答应说明无法确认并建议核对图书馆官方通知，不现场编出开放时间。这一轮用于展示资料边界。

如果现场时间有限，优先演示第 1 题和第 2、3 题：分别覆盖知识检索、工具调用和多轮记忆。

## 三、老师可能会问的问题

### 1. 什么是 Agent？本项目里的 Agent 做了什么？

Agent 可以理解为由语言模型负责理解问题和选择下一步操作、再由程序执行具体操作的系统。它不只是把问题发给模型生成一段话。本项目用 LangGraph 的 `StateGraph` 编排校园客服流程：先处理演示身份范围，再调用模型；如果模型提出工具请求，服务端执行工具并把结果交回模型，最后生成答复。工具调用有数量上限，状态查询和服务登记还会在后端校验身份与数据归属。

### 2. 什么是 RAG？项目中的检索流程是什么？

RAG 是“检索增强生成”：回答前先从外部资料中找相关内容，再让语言模型依据这些内容作答。这样更新校园知识时可以更新资料和索引，不必为了每条新规定重新训练模型。

本项目的流程是：整理公开校园资料并保留标题、日期、链接和适用范围等元数据；按固定长度切分文本；为文本块生成向量并存入索引；用户提问时也生成问题向量，检索相似文本块；再将命中内容交给模型组织答案并按提示列出来源。工程版使用持久化 Chroma 索引，检索前 5 个匹配结果，并排除标记为 `archive_not_for_current_answers` 的归档资料。没有足够证据时，提示词要求说明无法确认，不猜当前政策或开放时间。

### 3. 什么是 Embedding？为什么要用它？

Embedding（文本向量）是把文本转换成一组数字，使语义相近的文本在向量空间中更接近。用户的提问和资料文本因此可以按语义相似度匹配，不要求关键词完全一致。

本项目用本机 Ollama 提供的 `bge-m3:latest` 生成 1024 维向量，检索采用余弦相似度。余弦相似度比较两个向量方向的接近程度，值越高通常表示语义越相近；它只是检索排序依据，不等同于答案正确率。Embedding 模型负责把文本变成向量；回答文本则由配置的对话模型（演示启动器默认 `deepseek-flash`）生成。这是两个不同环节。资料向量来自项目保存的索引快照，用户问题在检索时实时向本机 Ollama 生成向量。

### 4. 什么是 Memory？它和 RAG 有什么区别？

Memory 是对话过程中的会话记忆，用来让系统在后续轮次理解“这条记录”“刚才提到的事情”等指代。RAG 检索的是校园资料，Memory 保存和使用的是当前对话上下文；一个提供外部知识，一个延续本轮交流。

本项目用 LangGraph SQLite checkpointer 按对话线程保存消息。模型每轮最多接收最近 4 轮用户对话作为上下文，页面仍可读取该线程的完整历史。切换合成演示身份时，程序会清除旧身份的历史消息（保留当前最新问题），避免把上一身份的工具结果带入下一身份。这里演示的是线程级短期记忆，不是已建立的真实学生长期画像。

### 5. 文本为什么要切块？为什么用 500 字、重叠 80 字？

如果整份文件作为一个检索单元，相关规定可能被无关内容稀释；切成文本块后，检索可以把较相关的部分交给模型。当前固定索引使用每块 500 个字符、相邻块重叠 80 个字符。重叠用于减少规定恰好被切在边界、前后语境丢失的情况。块太小可能缺少上下文，块太大则会带入更多无关内容，这组参数是当前实验快照采用的配置。

### 6. 模型如何查状态或“转人工”？

模型不会直接访问数据库。它先通过结构化工具调用提出查询或服务登记请求，服务端再校验参数、身份和记录归属，并执行允许的 SQLite 操作，随后模型根据工具结果向用户说明。状态记录按 `record_id` 和服务端注入的合成身份共同查询。所谓“转人工”在本项目中只会创建本地模拟工单，数据库标记为模拟数据，不会通知真实工作人员。

### 7. 这里的身份验证是真实校园账号认证吗？

不是。`SIM-USER-001` 等是课程演示身份，用于验证工具能否按记录所有者隔离数据；它不连接学校统一身份认证，也不能用于真实学生事务。实际部署还需要接入学校认可的身份认证、权限管理和业务系统。

### 8. Chroma 和 NumPy 各自有什么作用？

工程版通过 Chroma 持久化保存向量并执行 Top-K 检索，便于作为服务运行；项目的原理验证路线还实现了 NumPy 余弦相似度检索，用于直观展示向量相似度排序。二者复用同一组校园资料和向量快照，侧重点是工程索引与基础算法实现。

### 9. 这个系统目前有哪些边界？

网页演示使用本机服务和本地合成办事数据，校园资料也来自项目固定快照；它没有接入学校真实办事系统、学生身份系统或真实人工坐席。政策和通知的时效仍要以学校最新正式发布为准。演示时我会以页面实际返回的检索来源和工具结果说明系统能力，不把模拟结果表述成真实办理进度。

### 10. 项目怎样减少模型编造信息？

涉及校园事实时，提示词要求先检索资料，再按命中来源的日期、适用范围和链接回答；检索时排除专供归档的资料。证据不足就说明无法确认，不猜政策、开放时间或办理结果。这些措施能降低无依据回答的概率，但不能保证模型绝不出错，所以演示时仍要核对页面给出的来源和工具结果。

## 四、代码定位

如果老师希望看实现位置，可在项目目录中打开：

- Agent 流程与会话上下文：`src/agents/campus_customer_service.py`
- 检索、状态查询和模拟服务工具：`src/agents/campus_tools.py`
- Embedding 调用、RAG 搜索和索引加载：`src/campus/embeddings.py`、`src/campus/knowledge.py`、`src/campus/runtime.py`
- 分块、向量检索和 Chroma 适配器：`src/campus/chunking.py`、`src/campus/retrieval.py`、`src/campus/retrieval_chroma.py`
- 合成数据的归属校验与本地模拟工单：`src/campus/tools/status.py`
- 网页前端与演示身份设置：`src/streamlit_app.py`
